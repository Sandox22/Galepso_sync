Módulos de Inserción / Actualización

Cada dominio de datos tiene su propio .prg autocontenido. El patrón es uniforme en todos:

① SQLSTRINGCONNECT ② DELETE FROM tabla ③ DO WHILE !EOF() ④ SQLEXEC(INSERT) ⑤ SQLDISCONNECT

Es un full-replace por tabla (no sync incremental), excepto tsincronizacion que guarda timestamps.

No usan DO WHILE como loop principal ni polling en código PRG. Usan controles Timer nativos de VFP embebidos en el formulario frmrespaldos.scx.
📤
tmrEnviar
Dispara envío de datos
inventario + cxc + cajas
📥

Dispara recepción de datos
pedidos + recibos + devoluciones
⏱️
Timer1
Timer auxiliar
Se auto-deshabilita tras ejecutar

Flujo de ejecución paso a paso

1

Inicio de la aplicación

principal.prg abre el formulario con DO FORM frmrespaldos + READ EVENTS. El formulario queda residente con los controles Timer configurados con un TimerInterval en milisegundos.

2

Disparo automático por Timer

Cada Timer.TimerEvent llama a los métodos EJECUTAR_TAREA (envío) y EJECUTAR_TAREA_REC (recepción) del formulario. Internamente ejecutan DO inventario, DO cxc, DO pedidos, etc.

3

Ejecución dentro de cada módulo

Cada PRG abre su propia conexión ODBC con SQLSTRINGCONNECT, ejecuta DELETE FROM tabla (borrado total), recorre el cursor local con DO WHILE !EOF(), inserta fila a fila con SQLEXEC(INSERT), y cierra con SQLDISCONNECT.

🔴
Riesgo crítico: El patrón DELETE + INSERT significa que durante la sincronización hay una ventana de tiempo donde los datos en MySQL están vacíos. Si el proceso falla a mitad, se pierde data parcialmente.
